CASE STUDY / 001

AI 업무 실행 기록

하나의 요청이 검토 가능한 요구사항 초안으로 바뀌는 과정을 살펴보세요.

이 화면은 가상 사례를 사용한 설계 시제품입니다. 아래 분석은 미리 작성한 예시이며, 실시간 AI 모델이 실행되지 않습니다.

실행 단계

사례 ID DEMO-001
상태 검토용 예시
01 / REQUEST

업무 요청

“거래처 정보를 등록했는데 다른 업무 화면에서 또 입력해야 합니다. 한 번 등록한 정보를 다시 쓸 수 있게 해주세요.”
요청 목적반복 입력 감소
입력 자료공개용 가상 문장 1개

이 한 문장만으로는 어떤 화면과 어떤 필드가 중복되는지 확정할 수 없습니다.

02 / ANALYSIS DRAFT

AI가 작성할 분석 초안

요구사항 후보

  1. 기존 거래처 정보를 다른 업무 화면에서 검색해 선택한다.
  2. 선택 후 재사용할 필드를 명확히 정의한다.
  3. 원본 정보가 변경될 때 기존 기록에 미치는 영향을 결정한다.

확인이 필요한 질문

  • 중복 입력이 발생하는 화면과 필드는 어디인가?
  • 거래처를 선택할 권한은 누구에게 있는가?
  • 입력 시점의 정보를 보존해야 하는 업무가 있는가?

이 내용은 예시 초안입니다. 실제 모델 출력이나 확정된 제품 요구사항을 뜻하지 않습니다.

03 / EVIDENCE

근거와 미확인 사항

입력에서 확인
반복 입력을 줄이고 싶다

요청 원문의 “또 입력해야 합니다”와 “다시 쓸 수 있게”에서 확인됩니다.

추론한 후보
기존 거래처 검색·선택 기능

재사용을 구현하는 한 가지 방법입니다. 요청자가 이 방식을 지정하지는 않았습니다.

확인 필요
화면·필드·권한·변경 이력

현재 입력에는 관련 정보가 없습니다. 담당자의 추가 확인이 필요합니다.

04 / HUMAN DECISION

사람이 결정할 항목

?
검토 상태: 보류

실제 화면과 필드 범위를 확인하기 전에는 기능 요구사항을 확정하지 않습니다.

다음 작업

  • 중복 입력 화면과 필드 목록 수집
  • 거래처 정보 접근 권한 확인
  • 원본 수정 시 과거 기록 처리 방식 결정

실제 승인 기록이 아닙니다. 검토자가 어떤 결정을 남길지 보여주는 예시입니다.
