01 / PROBLEM → APPROACH

에이전트에게 일을 맡기며
부딪힌 세 가지

01

맥락이 한 번에 들어가지 않는다

제품 하나의 기획 자료를 통째로 넣으면 에이전트의 작업 창이 넘칩니다. 그래서 자료를 메뉴 계층 단위로 나눠, 지금 손대는 화면에 필요한 맥락만 불러오게 했습니다. 항상 읽는 요약, 메뉴 단위 개요, 화면 단위 상세의 세 단계입니다.

02

작업이 끊기면 처음부터 다시

사용량 한도나 네트워크 문제로 세션이 끊기면 어디까지 했는지 잃어버렸습니다. 에이전트가 작업 전후에 진행 상황을 파일에 저장하고, 다음 세션에서 그 지점부터 이어 가도록 했습니다.

03

사람마다, 날마다 결과가 다르다

같은 요청에도 문서 형식과 저장 위치가 매번 달랐습니다. 지켜야 할 규칙을 문서로 정하고, 커밋 메시지·저장 위치·비밀 정보 노출 같은 항목은 작업할 때마다 자동으로 검사하는 훅으로 막았습니다.

플러그인: 혼자 개발, 검증 뒤 배포

기능은 개발 저장소에서만 고치고, 빌드와 검증을 거친 버전만 배포 저장소에 올립니다. 동료는 배포 저장소만 바라봅니다.

업무 맥락: 모두가 함께 쓰는 저장소

쌓아 둔 기획 맥락은 사내 Git 서버의 공용 저장소에 두고, 비개발자도 쓰도록 세션을 시작할 때 받고 마칠 때 올리는 과정을 자동화했습니다. 충돌이 나면 자동으로 합치지 않고 백업 브랜치에 따로 보관합니다. 개인 작업 폴더는 동기화에서 뺐습니다.

개발 저장소의 커밋은 2026-04-14부터 센 값입니다. 그 전의 초기 버전(v0.3~v0.5)은 변경 이력에만 남아 있습니다.

03 / TIMELINE

버전 이력으로 본
8개월

  1. 2026-03첫 버전

    메뉴 계층 단위로 맥락을 나눠 불러오는 구조, 작업 세션 저장, 일정 시트 연동, 문서 정리 기능으로 시작했습니다.

  2. 2026-04업무 표준화

    유지보수 요청 검토 절차를 표준으로 만들고, 모두가 쓰는 공용 영역과 개인 작업 영역의 경계를 나눴습니다.

  3. 2026-05배포 준비와 온보딩 자동화

    새 사용자의 PC에 Git 신원과 비밀 정보 검사 훅을 자동으로 설정하고, 세션을 시작하고 마칠 때 공용 저장소와 자동으로 동기화하게 했습니다.

  4. 2026-06자동 업데이트

    사내 배포 저장소는 자동 업데이트가 기본으로 꺼져 있어, 새 버전이 나와도 각자 직접 받아야 했습니다. 온보딩 단계에서 자동 업데이트를 켜 동료가 늘 최신 버전을 쓰게 했습니다.

  5. 2026-07설정 누락 막기

    실제 온보딩에서 도구 등록은 끝났는데 인증을 건너뛰어 진행이 멈추는 일이 여러 번 생겼습니다. 인증을 확인하기 전에는 완료라고 하지 않도록 순서를 고정했습니다.

  6. 2026-10배포 전 사실 검증

    배포한 버전을 에이전트 7개로 다시 검증하다, 그 버전이 새로 만든 결함 9건(사실 오류 7건, 문서 누락·불일치 2건)을 찾았습니다. 그 뒤로는 새로 적은 사실을 배포 전에 따로 검증하는 단계를 거칩니다.

결과

사용 범위

2026년 4월 베타 사용자 3명과 함께 쓰기 시작했습니다. 6월부터는 온보딩을 마친 사용자 모두에게 자동 업데이트가 켜지도록 해, 새 버전이 나오면 따로 받지 않아도 최신 버전을 쓰게 했습니다.

명령 하나로 묶은 일

유지보수 요청은 이슈 번호 하나를 넣으면 조회, 관련 자료 분석, 검토안 저장까지 이어서 처리합니다. 새 사용자 준비도 명령 한 번으로 Git 신원, 비밀 정보 검사 훅, 개인 작업 폴더를 설정합니다.
